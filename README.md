# MCZJU 小游戏框架

本核心插件 `MCZJUGameCore`（简称 `MGC`）实现了许多常见小游戏中的重复逻辑，如独立物品栏、等待加入游戏、多个游戏房间及对应参数设置与保存等，让你专注于游戏开发流程。

下面称基于本插件开发的小游戏插件为**具体插件**，一些说明以起床战争为例。

## 设计思路

- 设计了多个组件管理器（manager），具体插件只需和这些管理器打交道。
- 用模板方法 + 多态，比如抽象基类 `AbstractGame` 下可以有 `SinglePlayerGame`、`MultiPlayerGame` 甚至更多子类，重复逻辑写在抽象基类中。
- 用策略模式（strategy），让框架变得更容易扩展。例如对于等待加入游戏的策略 `GameWaitStrategy`，默认行为是人数到达上限时直接开。还可以再实现其他 strategy 提供更多的等待逻辑，具体插件可以自己选择 (getStrategy方法)。
- 为 Bukkit 的 `Player` 添加拓展结构 `PlayerExt`，它本身只有 `player` 一个字段，但通过对管理器的调用，实现了 `isInParty` 等方法，让开发更符合直觉。（`player.getParty()` 比 `playerManager.getParty(player)` 用起来更便捷）。

## 代码逻辑

### 具体插件需要关心并实现的模块

`AbstractGame`：小游戏基类。1 个 `AbstractGame` 子类就是 1 个游戏。它提供了 `onGameStart` 等 hook，每个具体插件需要写一个继承它的子游戏类，来写自己的游戏逻辑。
  `MGC` 为单人游戏专门提供了 `SinglePlayerGame` 抽象类，未来还会实现 `MultiPlayerGame` 等更多的抽象类，让开发更简单。

> 如果你开发的小游戏是单人游戏，你可以直接继承 `SinglePlayerGame`（它本身也是 `AbstractGame` 的子类），而非 `AbstractGame`。
> 可以理解为，`SinglePlayerGame` 进一步实现了部分只适用于单人游戏的逻辑。

1 个游戏可以有 1 个或多个房间，这些房间拥有相同的参数（例如出生点位置），但具体值不同（不同房间的出生点不同）。

通过创建一个 `AbstractGameRoom` 抽象基类的子类来定义房间参数。如果直接继承 `JsonGameRoom`，还可以打开 `MGC` 提供的编辑菜单，直接修改这些值。

> 一些游戏本身的设置，建议具体插件自行配置，例如起床战争中，每局持续多少时间，开局需要发什么装备等。

> 部分游戏并没有“房间”概念，比如所有玩家都在一个公共场景中游玩的游戏，也需要写 `AbstractGameRoom` 用于注册，用来当占位符，代表有 1 个空闲房间。

游戏的整个生命周期由 `MGC` 管理，将自动根据 `AbstractGame` 子类中设置的等待策略启动游戏。

`MGC` 会识别玩家是否在游戏中，阻止它同时加入另一个游戏。`MGC` 还使玩家在大厅和每个小游戏中时，物品栏、末影箱、经验均互相独立。

游戏进行中，具体插件自行处理游戏逻辑，例如资源刷新等。

> 有些特殊的场景类游戏（比如大厅钓鱼）不需要本插件进行生命周期管理，就不用实现 `AbstractGame` 的子类并注册。 
> 这种情况下，主菜单不会出现该游戏的入口，无法享受 `MGC` 自带的每个小游戏独立物品栏。
> 但仍然可以调用 `ScoreManager` 并注册分数排行榜，或使用 `MGC` 提供的其他便捷工具。

### 由 `MGC` 完成的模块

> 本部分只列出具体插件可能需要关心、调用的模块。
> 
> 建议通过阅读 `MGC` 的源码，进一步了解相关功能。

策略:

用于处理具体插件中共同面临的一些事件，每一个策略写 1 个实现类。

- `GameWaitStrategy`：游戏等待策略，比如最少开始玩家、最多开始玩家、计时时间、1人游戏直接开始等。
- `PlayerQuitStrategy`：玩家退出策略，游戏是继续进行，还是直接停止等。

其他功能模块：

- `PlayerExt`：为方便小游戏开发，为 Bukkit 的 `Player` 接口新增了一些扩展方法。
- `Menu`：基于虚拟箱子的菜单。具体用法请查看[示例插件](./docs/guide.md)中给出的例子。
- `Party`：组队系统（类似于 hypixel 的），处理需要多人参与游戏的情况。
- `ScoreManager`：单局的计分管理器，具体插件调用它来设置玩家分数。未来会添加排行榜功能。
- `ItemManager`：特殊物品管理器，提供物品辨别（`isThis`）等功能（识别物品的 pdc）。

工具：

详见[示例插件](./docs/guide.md)中的说明。

## 如何贡献

整体框架已经搭好了，可以开始开发具体插件了。 更多需要实现或修改的模块，请查看远程仓库 issue。

还有些地方需要改善、或者还没写，详见issue。

另外目前有很多细节上的问题，有很多提示没写，比如玩家加入游戏后没提示游戏现在是几缺几，也可以提issue，然后进行小的修改。

关于多人合作开发规范，详情请见[链接](https://github.com/mczju-ops/mczju-infra-docs/blob/main/dev/contributing.md)。
